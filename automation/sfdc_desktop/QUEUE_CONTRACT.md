# CSS / Google Sheets -> Salesforce staging contract

The existing production Google Sheets CSS tabs are **not rewritten**. The identified
`automation/css/bi_mail_review_sync.py` consumes the `BI Mail Review & Exclusions`
and `Unanswered Emails Auto` tabs; exclusion review decisions are **not**
permission to create Salesforce Activities.

Until SFDC browser permissions and tab schemas have been audited, provide an
explicitly reviewed CSV exported locally or generated by a separately approved
Sheets read-only job.

Input header:
```csv
source_id,decision,account_key,subject,description
```

Decision must equal `READY_FOR_SFDC` or `APPROVED_FOR_SFDC`.
`account_key` is a stable association key required for preflight, not an SFDC
Record ID. The Task staging queue deliberately excludes associations: before
production saves, lookup and verify an existing SFDC Account/Contact/Opportunity
in the UI and populate the actual relationship field with a verified selector.

Staging command:
```powershell
.\.venv\Scripts\python.exe automation\sfdc_desktop\queue_adapter.py --input reviewed.csv --output staging.csv
```

Do not commit either CSV. Do not treat staged rows as completed Salesforce actions.

## Production gates still missing

  after crash/retry.
- Verify Contact/Account/Opportunity links through Salesforce UI.
- Enforce approval on external/customer-facing or bulk record writes.
- Implement atomic ledger: PENDING -> CLAIMED -> SAVED_VERIFIED, with review for
  ambiguous or partial saves.
- Keep customer mail and record data out of GitHub CI logs and artifacts.
